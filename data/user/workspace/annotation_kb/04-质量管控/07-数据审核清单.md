# 数据审核清单

数据标注完成后的审核是实现质量控制"最后一道防线"的系统化工具。本清单涵盖完整性、准确性、规范性和特殊情况四大类检查项。

## 一、完整性检查

### 1.1 标注数量完整性

- [ ] **标注文件数量 = 原始数据数量**  
  逐一核对：每张原始图片/每段原始文本是否都有对应的标注文件？
  
- [ ] **无空标注**  
  检查所有标注文件，确认每个文件的标注结果不为空（除非标注规范明确允许"无目标"且标记了 `empty` 属性）。

- [ ] **标注类别全覆盖**  
  任务要求的所有标注类型在标注文件中均有体现。例如要求标注 car、person、bicycle 三类，检查是否有某一类在所有文件中都未出现（可能是标注员忽略了该类别）。

### 1.2 标注字段完整性

- [ ] **必填字段已填写**  
  - 目标检测：每个框都有 `label`（标签名称）和 `bbox`（坐标）字段
  - 图像分类：每张图都有至少一个 `choice`（分类结果）
  - 关键点：每组关键点的数量等于要求数量（如 17 点人体姿态）

- [ ] **可选字段不存在缺失值**  
  如遮挡标记（`occluded`）、截断标记（`truncated`）等属性字段，不应存在空字符串或 `null` 值。

### 1.3 元数据完整性

- [ ] **标注人员信息**：每个标注记录应包含标注员 ID 或姓名（用于追溯和绩效统计）
- [ ] **标注时间**：标注完成时间戳存在且合理（不应出现标注时间为 1970-01-01 的异常数据）
- [ ] **数据来源**：如果数据来自多个渠道（如爬虫、摄像头、公开数据集），应标记数据来源

---

## 二、准确性检查

### 2.1 标签准确性

- [ ] **标签名称合法**：所有标签值都在标注规范定义的标签列表中（使用 Python 脚本自动化检查）
- [ ] **标签选择正确**：逐张检查，确认标注类别与实际目标类别一致。重点检查：
  - **相似类别**：如 sedan vs SUV、truck vs bus（容易混淆的类别）
  - **罕见类别**：如消防栓、路障等出现频率低的类别（标注员可能不熟悉）
  - **多义类别**：如"vehicle"（是否包含自行车？应在规范中明确）

### 2.2 定位准确性

- [ ] **框边缘贴合度**：标注框的边沿与目标真实边缘的距离 ≤ 5 像素（或根据项目标准），抽查方式：
  - 选取 10-20 张典型图片
  - 在放大视图（至少 200%）下逐边检查
  - 使用标注工具的距离测量功能（如有）

- [ ] **最小外接矩形原则**：确认标注框为目标的"最小外接矩形"，即框的四边恰好接触目标的边界（不应包含过多背景空间）

- [ ] **关键点位置准确**：关键点标注中，每个关键点都落在正确的解剖/结构位置（如"鼻子"关键点落在鼻尖，而非鼻梁）

### 2.3 边界案例确认

- [ ] **遮挡目标**：被遮挡但可见比例 > 30% 的目标是否已标注？标注框是否覆盖可见部分（而非推测被遮挡部分）？
- [ ] **截断目标**：图片边缘被截断的目标是否已标注？
- [ ] **密集目标**：多个目标重叠或紧密排列时（如停车场中的汽车），是否每个独立目标都有独立标注框？
- [ ] **模糊目标**：运动模糊或对焦模糊的目标是否按照规范标注？（检查是否因模糊而漏标）

## 三、规范性检查

### 3.1 格式规范性

- [ ] **文件格式正确**：
  - JSON 文件可正常解析（无语法错误、编码错误）
  - XML 文件符合 VOC 格式 Schema
  - TXT 文件（YOLO 格式）每行符合 `class_id x y w h` 格式

- [ ] **坐标格式正确**：
  - VOC：`[xmin, ymin, xmax, ymax]`，xmin < xmax，ymin < ymax
  - COCO：`[x, y, width, height]`，width > 0，height > 0
  - YOLO：`[x_center, y_center, width, height]`，所有值在 0-1 之间

- [ ] **坐标值在合理范围内**：
  - `x` 和 `y` 值在 `[0, 图片宽度/高度]` 范围内
  - 框的尺寸 > 0（没有面积为 0 的框）

### 3.2 命名规范性

- [ ] **文件命名符合规范**：
  - 标注文件名与原始文件名对应（如 `001.jpg` → `001.xml` 或 `001.txt`）
  - 无特殊字符（空格、中文、emoji 等）在文件名中

- [ ] **标签命名一致性**：
  - 同一个类别在所有文件中名称完全一致（不能有的写 `car` 有的写 `Car`）
  - 标签使用统一的大小写（如全小写 `car`、`person`）

### 3.3 提交规范

- [ ] **无草稿状态遗留**：所有标注任务均已提交（非草稿状态）
- [ ] **无跳过/取消标记**：没有人为主观跳过不应跳过的任务（如"太难了不想标"而点跳过）
- [ ] **无大量同一人短时间批量提交**：如果某个标注员在 1 分钟内提交了 50 张图片（远超出正常标注速度），应重点检查该批次的标注质量

## 四、特殊情况标记

### 4.1 遮挡处理

- [ ] 被遮挡目标的 `occluded` 属性已标记
- [ ] 严重遮挡（可见比例 < 30%）的目标已按规范标记（如 `ignore` 区域或直接不标注）

### 4.2 截断处理

- [ ] 图片边缘被截断的目标的 `truncated` 属性已标记

### 4.3 困难样本

- [ ] 对于标注规范定义的"困难样本"（如严重模糊、极端光照），是否已按规范处理（如添加 `difficult` 标记）？

### 4.4 人群/密集物体

- [ ] 密集人群/密集物体（无法逐个体标注）是否已按规范处理？（如标注为 `crowd` 区域，使用 `iscrowd=1` 标记，或使用多边形标注整体区域）

## 五、审核抽样检查表

### 每批次抽检记录模板

| 检查项 | 检查方法 | 抽样数量 | 通过标准 | 实际结果 |
|--------|---------|---------|---------|---------|
| 文件完整性 | 脚本自动比对 | 全部 | 100% | ___/___ |
| 标签合法性 | 脚本自动比对 | 全部 | 100% | ___/___ |
| 坐标越界 | 脚本自动检查 | 全部 | 100% | ___/___ |
| 标签准确性 | 人工逐张检查 | 按抽检比例 | ≥ 95% | ___/___ |
| 定位准确性 | 人工放大检查 | 抽检样本内 50% | ≥ 95% | ___/___ |
| 命名规范 | 脚本自动检查 | 全部 | 100% | ___/___ |

### 审核结论

- [ ] **通过**：各项指标达标，数据可以入库
- [ ] **有条件通过**：非关键检查项不达标，标注员修正指定项后可入库
- [ ] **退回返工**：关键检查项不达标（如标签准确率 < 95%），整批退回标注员修正
- [ ] **废弃**：标注质量严重不达标且修正成本 > 重新标注成本（罕见情况）
