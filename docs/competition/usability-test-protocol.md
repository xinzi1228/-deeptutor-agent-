# 真实用户测试协议（标注星图 · 竞赛证据）

日期：2026-08-15
版本：1.0

## 1. 目的

用可复查的真实用户数据证明纵向优化是否提升完成率、速度、理解和易用性，并形成可直接用于竞赛说明、答辩和演示视频的匿名证据包。系统只负责采集与生成，**不得虚构参与者、补填缺失记录或把内部开发者测试冒充目标用户测试**。

## 2. 参与者与授权

- 固定最小样本：**2 名目标学生**（`S01`、`S02`）和 **1 名职教教师**（`T01`）。
- 测试前逐项确认并记录知情同意（`participate` / `screen_record` / `audio_record` / `quote` / `retention`）。不同意录音或引用不影响参与测试。
- 参与者可随时停止，并可申请删除个人材料；删除动作写入审计，汇总报告重算并标记版本。
- 姓名、手机号、学号、学校和人脸不得进入默认证据包。系统内只保存 `S01` / `S02` / `T01` 匿名编号。

## 3. 两轮方法

同一参与者完成优化前 **A 轮** 与优化后 **B 轮**。两轮都使用交通道路车辆/行人矩形框任务，知识点与难度一致、素材不同，避免记住答案。任务脚本、测试电脑、浏览器与网络条件尽量一致。

### 学生流程

1. 登录并选择学习档案。
2. 完成三题入门诊断。
3. 学习遮挡和贴边规则。
4. 完成车辆/行人框选。
5. 查看质检、评分和教练解释。
6. 完成一次订正。
7. 找到成长报告和下一任务。

### 教师流程

1. 找到被分配学生与当前任务。
2. 查看报告和待处理问题。
3. 在代管模式添加反馈或分配下一任务。
4. 检查内容引用与一条审核候选。
5. 查看用户测试汇总并核对原始记录索引。

主持人只按脚本提示，不替参与者操作。卡住后先计时和记录原因，再提供分级帮助。

## 4. 采集指标

- 任务完成率与各阶段完成状态；
- 总耗时、各阶段耗时、首次可操作和首个模型状态时间；
- 卡住次数、求助次数、错误数、重复提交和返回上一步次数；
- 标注漏标、错标、贴边错误与订正成功率；
- 1–5 分的易懂、易用、信任、继续使用意愿；
- 访谈原话、观察记录和严重问题；
- 测试版本、内容版本、模型配置引用、Label Studio 连接状态和设备条件。

缺失指标保留 `null` 并说明原因，**不用 0 代替**。所有时间使用服务端或同一单调时钟；人工修正须保留原值、修正值、理由和操作者。

## 5. 数据与证据结构

每次测试生成不可变 `study_run`，引用匿名参与者、轮次、场景、任务版本、同意范围和事件文件。报告使用确定性聚合器生成，包含源记录 ID 与数据哈希。

证据包目录：

```text
competition-evidence/
  README.md
  methodology.md
  participants-anonymous.csv
  runs-index.json
  metrics-summary.json
  charts/
  quotes-approved.md
  issues-and-actions.md
  source-hashes.json
  demo-script.md
```

录屏和录音不默认复制进提交包，只在索引中保存受控位置和授权状态。对比图必须走可信可视化协议，绑定数据集版本与哈希。

## 6. 分析规则

- 样本很小，**不声称统计显著性**。主要报告每位参与者 A/B 变化、三人中位数/范围、共同卡点和定性反馈。
- 任何"提升百分比"都必须展示原始分子分母；样本缺失时不得外推。
- 问题按阻断、严重、一般、建议分级，并关联修复提交和复测结果。
- 竞赛摘要必须区分"真实观察""参与者主观反馈"和"团队推断"。

## 7. 报告生成器拒绝规则

报告生成器拒绝以下情况：参与者编号不合法、同意缺失、任务版本未知、事件时间倒序、指标引用不存在或哈希不匹配。允许生成"不完整草稿"，但必须醒目标注不可用于正式提交。

## 8. 验收标准

- 自动测试覆盖指标聚合、缺失值、A/B 配对、删除后重算、人工修订历史、哈希校验、跨参与者权限和脱敏导出（`pytest tests/services/test_usability_report.py`）。
- 人工验收必须真实完成 2 名学生和 1 名职教教师的两轮测试；随机抽取报告中的耗时、错误数和原话，与事件记录及授权逐条核对。
- 代码完成不代表本任务完成。只有三名真实目标用户完成两轮测试、授权可核验、报告可回查、严重问题有处理结论、匿名证据包通过人工复核，才算完成。
