# 第三轮优化 E7 实现计划：Dangling tool call 修补

> 依据：`docs/superpowers/specs/2026-08-07-deerflow-borrow-design.md` E7。借鉴 DeerFlow `dangling_tool_call_middleware.py:36-88`：用户中断/取消产生的半截工具调用，在消息历史里 AI 有 tool_calls 但缺对应 tool 结果 → 插入合成"该调用被中断"占位，避免模型困惑/报格式错。TDD。

## 现状（已核实）
- `agentic_pipeline.py` `_build_loop_messages`（L352-393）：从 `context.conversation_history` 构造初始 messages，仅取 role∈{user,assistant} 的 content（L377-391）。**tool 角色消息不进 history**。
- 场景：用户点 stop 中断一轮 → turn 结束；下一 turn 的 conversation_history 可能含 assistant 消息带 `tool_calls` 字段但缺 tool 结果。

## 设计
在 `_build_loop_messages` 遍历 history 后、返回前，做一次**补洞**：
- 遍历构造出的 messages，遇到 role=assistant 且带 `tool_calls`（list 非空，dict 含 `id`）时，收集 `tool_call_id` 集合
- 扫描其后的消息，若某 tool_call_id 没有对应 `role=tool` 且 `tool_call_id` 匹配的消息 → 在紧贴 assistant 之后插入合成：
  ```python
  {"role": "tool", "tool_call_id": tc_id, "content": "（该工具调用被中断，未返回结果）"}
  ```
- 仅在 history 层补洞（不处理本轮 loop 内的正常调用——loop 自己保证 assistant+tool 成对）

## 改动 `deeptutor/agents/chat/agentic_pipeline.py`
新增私有 `_patch_dangling_tool_calls(messages: list[dict]) -> list[dict]`：
1. 先收集所有 assistant 消息的 tool_calls ids 与所有 tool 消息的 tool_call_ids（建集合）
2. 对每个缺失的 id，在对应 assistant 消息后插入合成 tool 消息（保持顺序）
3. `_build_loop_messages` 末尾调用（`_prepare_messages_with_attachments` 之前）
工具消息的 id 字段名需确认（`tool_call_id`）；assistant tool_calls 项结构（dict `id`）。
