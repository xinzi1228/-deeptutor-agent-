# 第三轮优化 E2 实现计划：澄清类型化（ask_user 加 clarification_type）

> 依据：`docs/superpowers/specs/2026-08-07-deerflow-borrow-design.md` E2。**现状核查**：`ask_user` 已支持批量问题卡片 + pause 中断 + 回复恢复（等价 DeerFlow 澄清中断）。E2 增量 = **澄清类型化**（DeerFlow 5 类：missing_info / ambiguous_requirement / approach_choice / risk_confirmation / suggestion）——每条澄清问题带类型，前端显示徽标，强化"诊断优先"教学法。TDD。

## 现状（已核实）
- `deeptutor/tools/ask_user.py`：`AskUserQuestion{id, prompt, options, header, multi_select, allow_free_text, placeholder}`；`build_ask_user_payload` 规范化 + 校验
- 前端 `web/components/chat/home/AskUserOptions.tsx`：`AskUserQuestion` interface（L30）+ 卡片 tab 渲染
- route_input 已 detect confuse → Coach 调 ask_user

## 改动

### 1. 后端 `deeptutor/tools/ask_user.py`
- 模块级 `CLARIFICATION_TYPES: tuple[str, ...] = ("missing_info", "ambiguous_requirement", "approach_choice", "risk_confirmation", "suggestion")`
- `AskUserQuestion` 加 `clarification_type: str | None = None`；`to_dict` 带上
- `build_ask_user_payload`：解析 question dict 的 `clarification_type`，若在 CLARIFICATION_TYPES 则保留，否则置 None（非法值不报错，宽松）；默认 `approach_choice`（若提供 `_default_clarification_type` 参数可选，默认为 approach_choice）

### 2. 前端 `web/components/chat/home/AskUserOptions.tsx`
- `AskUserQuestion` interface 加 `clarification_type?: string | null`
- 类型徽标映射 + 渲染：在卡片顶部（intro 附近）或每 tab 标题旁显示小徽标，中文标签：
  - missing_info → 缺信息 · ambiguous_requirement → 需求模糊 · approach_choice → 方法选择 · risk_confirmation → 风险确认 · suggestion → 建议
- 无类型则不渲染（向后兼容）

### 3. PERSONA（源 + 运行时副本）
`deeptutor/services/persona/presets/annotation-coach/PERSONA.md`「输入分诊」段（找 ask_user/澄清 相关行）追加一句：
`用 ask_user 澄清时给每条问题标 clarification_type（missing_info 缺信息 / ambiguous_requirement 需求模糊 / approach_choice 方法选择 / risk_confirmation 风险确认 / suggestion 建议），让学生明白为何被追问。`
同步运行时副本（SHA 校验，不 git add）。

### 4. 测试
- 找现有 ask_user 测试（`tests/tools/test_ask_user.py` 或 build payload 相关）：
  - payload question 含合法 clarification_type
  - 非法类型 → 置 None（或默认 approach_choice）
  - 未提供 → 默认 approach_choice
