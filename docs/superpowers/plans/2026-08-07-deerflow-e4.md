# 第三轮优化 E4 实现计划：记忆置信度 + token 预算注入（MVP）

> 依据：`docs/superpowers/specs/2026-08-07-deerflow-borrow-design.md` E4。借鉴 DeerFlow facts confidence（≥0.7 门控 + 置信度降序 + token 预算注入）。**MVP 范围**：`Document` 条目支持 `confidence`/`source` 字段（MD 行尾注释持久化，往返兼容）；读端（read_memory / read_bucket / bucket_overview）按 confidence 降序 + token 预算截断。consolidator 生成 confidence 留 P2（需改 LLM op schema）。TDD。

## 现状（已核实 document.py）
- `Entry{id, section, text, refs, stale}`；bullet 行尾 `<!--{entry.id}-->{tail}`（tail 现为 `_STALE_MARKER`）
- `serialize` L258-262：`tail = f" {_STALE_MARKER}" if entry.stale else ""`
- `parse` L194-217：新/旧 bullet 分支构造 Entry，stale 从 regex group

## Task A — document.py confidence/source 字段
1. `Entry` 加 `confidence: float | None = None`、`source: str | None = None`
2. 模块级 `_CONF_RE = re.compile(r"<!--confidence=([0-9.]+)-->")`、`_SRC_RE = re.compile(r"<!--source=([^>]+)-->")`
3. `parse`：新/旧分支提取（`m.group` 或 line 扫描）→ `confidence=float(...) if match else None`（解析失败忽略）、`source=... or None`
4. `serialize`：tail 追加 `<!--confidence=0.80-->` / `<!--source=xxx-->`（有值才加；confidence 格式化 `:.2f`）
5. 往返：`parse(serialize(doc))` 保留 confidence/source；旧文档（无注释）→ None

## Task B — 读端置信度排序 + token 预算截断（store.py）
1. `store.read_memory()`（L3 拼接）+ `read_bucket()`：解析条目 → 按 confidence 降序（None 排最后）排列条目 → 按 token 预算截断
   - 预算：`MEMORY_TOKEN_BUDGET = 2000`（常量）；估算 `chars ≈ tokens * 2`（中文近似，取 `text` 长度按 2 chars/token）
   - 截断：累积超预算即停（保留高置信条目）；被截断时消息尾部追加 `（已截断，共 N 条记忆中的 M 条）`
   - 现有返回 str 不变；L3 的 preferences（无 confidence）仍保留（全局共享层不按置信度截断）
2. 测试（`tests/services/memory/test_bucket_paths.py` 或新建 `test_memory_confidence.py`）：
   - 高 confidence 条目排在低/None 前（read_bucket 输出顺序）
   - 超过预算 → 截断 + 提示；未超 → 全量
   - 旧文档（无 confidence）→ 全部排最后，仍返回（不丢）
   - document 往返测试：confidence/source 保留
