# 报告与提醒的可信自然表达设计

## 目标

让“标注星图”的学习报告和学习提醒更清楚、专业、可行动，同时保持所有结论可由已有学习数据追溯。学生或评委随机打开一份报告或提醒，应能快速回答三个问题：我现在怎样、为什么这样、下一步做什么。

本设计借鉴 `human-writing` 的表达原则：不靠泛化套话填充内容、每段都要推进信息、使用自然的中文节奏；同时保留项目既有 `verify_output` 的事实与引用护栏。它不以规避 AI 检测为目标，也不改变评分、学习记录、任务流或定时调度的业务规则。

## 范围与非目标

### 本次范围

- 进度页和对话中可见的学习报告摘要。
- 定时学习提醒，包括聊天内提醒与本地桌面通知的内容。
- 报告/提醒的离线表达质量检查。
- 覆盖典型学习状态的“金标准”样本文案与自动化测试。

### 非目标

- 不重写 `annotation_check`、F1 评分、学习记录、知识图谱和 cron 调度。
- 不为每条消息新增一次大模型审查调用。
- 不在第一版加入“有帮助/太长/太笼统”等用户反馈收集功能。
- 不用提醒内容推断或暴露私人信息；无充分数据时只输出通用、诚实的提醒。

## 方案选择

采用“程序保证事实和结构，AI 负责自然表达”的方案。

仅靠提示词虽然改动小，但不同轮次的稳定性和可测试性不足；完整的用户反馈平台需要真实使用数据，适合作为后续阶段。因此，本次先为报告与提醒建立可追溯的内容摘要和固定信息顺序，再允许 Coach 在不添加新事实的前提下进行中文润色。

## 数据流与组件

```text
学习记录 / 任务分数 / 能力图谱 / 定时任务
                ↓
       文案事实摘要（确定性生成）
                ↓
  报告或提醒的场景模板（固定信息顺序）
                ↓
       Coach 中文润色（不得增加事实）
                ↓
    离线表达质检 + 金标准样本回归
                ↓
进度页 / 聊天消息 / 桌面提醒
```

### 1. 文案事实摘要

新增独立、无副作用的摘要构建函数。它只读取既有数据，返回结构化字段，不直接生成面向学生的长文本。

建议字段：

- `completed_count`：本次或累计完成任务数。
- `average_f1`：有有效评分时的平均 F1；没有则为 `null`。
- `trend`：与上一次可比较任务的变化；数据不足则标记为未知。
- `strength`：已有证据支持的已掌握点。
- `priority_gap`：当前最值得处理的一个薄弱点；没有可靠证据则为 `null`。
- `next_action`：来自课程计划、任务流或当前任务的一个具体动作。
- `data_status`：`sufficient`、`partial`、`empty`，供模板安全降级。

摘要不得从单次偶然失误推断稳定画像，继续遵守项目现有 `unconfirmed/confirmed` 学习模式规则。

### 2. 报告场景模板

报告按以下顺序输出，默认每项 1 句，避免长篇复述数据：

1. **本次成果**：完成量和可确认的表现。
2. **当前判断**：分数或进步趋势，说明数据不足时如实说明。
3. **最关键改进点**：仅一个、有证据的薄弱点。
4. **下次行动**：一个可以立即执行的练习或复习动作。

报告必须避免“继续努力”“表现不错”等脱离事实的空泛结论。数据为空时使用“还没有足够练习数据形成判断；建议先完成……”的首轮报告，而非输出虚假的平均分或薄弱点。

### 3. 提醒场景模板

提醒由当前 cron 调度继续触发，但内容根据摘要选择场景：

- **首学/无数据**：说明预约事项，给出一项不超过 5 分钟的起步动作。
- **断点续学**：提及上次已完成的知识点或任务，并明确从哪里继续。
- **薄弱点复习**：仅在薄弱点有可靠学习证据时提及，并给出对应的单步练习。
- **进步巩固**：指出已确认的进步，建议一项巩固任务，避免过度庆祝。

每条提醒最多两句：第一句说明“为什么现在值得练”，第二句说明“打开后先做什么”。桌面通知和聊天内提醒共享同一事实摘要，但可按平台长度限制截短，不改变事实。

### 4. Coach 润色边界

Coach 接收“事实摘要 + 场景 + 长度限制”，只负责中文表述。

- 不得添加新的分数、标准、任务完成情况、学习偏好或薄弱点。
- 不得把 `partial` 或 `empty` 数据说成确定结论。
- 使用短句、具体名词和动作动词；避免连续套话、报告腔、夸张庆祝和一次给多项任务。
- 关键成绩与规范结论仍走既有 `verify_output` 护栏；表达质量本身不触发额外的在线 LLM 调用。

## 离线质检与测试

新增轻量、确定性的文本分析器，面向 CI 和本地回归使用，不拦截用户实时聊天。它输出警告而不是强行改写原文。

检查项：

- 是否含无事实支撑的绝对结论或数字。
- 是否只有泛化鼓励、没有明确下一步动作。
- 是否重复同一句式或同一夸奖词。
- 报告段落是否过长；提醒是否超过两句。
- 是否在数据不足时仍声明确定的趋势或薄弱点。

建立金标准样本，至少覆盖：新用户提醒、断点续学提醒、薄弱点复习提醒、进步报告、停滞报告、无数据报告。测试分为两层：摘要构建的字段正确性，以及最终文案是否满足长度、事实一致性、行动性和降级规则。

## 错误处理与降级

- 学习记录不可读或为空：生成无数据模板，不阻断 cron 调度或进度页。
- F1 缺失或无可比较历史：不计算趋势，不使用“提升/下降”。
- 未确认错误模式：不可作为提醒中的“你的薄弱点”。
- Coach 润色失败：回退到确定性模板文本，保证仍能发送可靠提醒和报告。

## 验收标准

1. 每份报告均包含成果、当前判断、一个改进点和一个下一步；数据不足时有诚实的降级文案。
2. 每条提醒不超过两句，包含提醒原因和一个可立即执行的动作。
3. 报告或提醒中的分数、趋势、薄弱点均可回溯到摘要字段和既有学习数据。
4. 金标准样本和离线质检在自动化测试中通过；不增加正常对话的额外大模型调用。
5. 既有学习记录、评分、cron 调度和 `verify_output` 测试保持通过。

## 后续阶段

第一版稳定后，再评估是否增加用户文案反馈按钮和聚合分析；该功能需要隐私说明、去标识化规则和足够的真实反馈数据，因此不纳入本轮实现。
