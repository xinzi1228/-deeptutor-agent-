# 黄金演示、性能回归与发布交接设计

日期：2026-08-14

状态：已批准，待实现
对应任务：竞赛纵向优化 5.1、5.2、5.3

## 1. 目标

把“看起来能运行”变成可重复验收：在普通竞赛电脑上稳定完成黄金学习闭环，外部服务故障时可控降级，全量构建与权限回归通过，最终说明文档与代码一致。

## 2. 黄金演示固定剧本

演示只使用交通道路目标检测主路径：

```text
登录/选择档案
→ 三题诊断
→ 遮挡与贴边讲解
→ 车辆/行人矩形框标注
→ 本地质检与正式评分
→ 标注教练解释
→ 学生订正
→ 成长报告与下一任务
```

总时长目标 5 至 7 分钟。其他场景、插件市场、生图和高级管理作为扩展能力展示，不插入主演示。演示前不得人工篡改学生记录制造理想报告。

## 3. E2E 场景

`golden-student-journey.spec.ts` 覆盖正常链路、刷新恢复、重复点击幂等、教学/专业模式切换和切换档案后的完全隔离。

`degraded-services.spec.ts` 分别模拟：对话模型不可用、Embedding 未验收、Label Studio 不可用、可视化失败和网络中断。预期行为：本地资料、草稿和规则检查尽量可用；页面说明未完成内容、保存状态和下一步；不展示伪造实时回答；恢复后不重复写入。

E2E 使用独立测试账号、档案和数据目录。测试结束只清理其自身数据，禁止删除用户开发数据。

## 4. 竞赛就绪检查器

`scripts/competition_readiness_check.py` 输出机器可读 JSON 和中文摘要，检查：

- Python、Node、浏览器和必要依赖版本；
- 后端、前端与 Label Studio 连接；
- 对话模型、Embedding、知识库引用和可选 imagegen 的真实状态；
- 数据目录写入权限、磁盘空间、端口占用和时钟；
- 必需内容版本、题库审核、黄金任务和测试账号；
- 明文密钥、未审核扩展和开发模式风险；
- 构建产物与提交版本。

检查器不得输出密钥、完整 Cookie、个人对话或标注正文。失败项给出修复建议和是否阻断演示。

## 5. 性能预算与测量

基准设备为 4 核 CPU、8 GB 内存、无独显、Chrome/Edge 和普通校园网络：

- 冷启动 3 秒内可操作；
- 页面切换 1 秒内出现核心内容；
- 成长首屏 2 秒内完成；
- 发送后 300 毫秒内出现真实处理状态；
- 模型正常时 5 秒内首字；
- 核心答案优先 15 秒内完成；
- 超过 30 秒可取消或重试；
- 取消、超时和重复点击不产生重复记录。

每项至少冷启动 3 次、暖启动 5 次，报告中写中位数和最差值。测量环境、代码提交、服务配置和缓存状态必须记录。未达到预算时先分析请求瀑布、重复状态和巨型组件，不以换电脑掩盖问题。

## 6. 回归门禁

后端：

```powershell
python -m ruff check deeptutor tests
python -m pytest -q
```

前端：

```powershell
cd web
npx tsc --noEmit
npm run test:node
npm run build
npm run perf:check
```

端到端：

```powershell
python scripts/competition_readiness_check.py
cd web
npx playwright test tests/e2e/golden-student-journey.spec.ts tests/e2e/degraded-services.spec.ts
```

发布前还需权限矩阵、知识引用、Label Studio 契约、对话预算、可视化哈希和真实用户报告测试通过。任何跳过必须写明原因、风险、临时措施和负责人，不得只写“环境问题”。

## 7. 连续三次演示规则

在目标竞赛电脑上从干净启动连续运行三次黄金演示。三次都要记录时长、故障、手工介入和外部服务状态。出现数据串档、正式结果丢失、无法取消、虚假就绪或必须开发者改数据库才能继续，均视为失败并重新计数。

## 8. 文档同步

最终修改 `AGENTS.md`、演示脚本、不可演示能力、Label Studio 能力报告、初始化说明和竞赛提交材料。必须明确：

- 学生四入口及教师/管理员工作台；
- 教学模式与专业模式的职责；
- 草稿、正式提交、修订和评分版本；
- Label Studio 统一账号网关与管理员内部入口；
- Embedding、imagegen、外部模型的实际配置状态；
- 真实可用能力、受控降级、已知限制和外部门槛；
- 最终测试命令、代码提交和结果时间。

删除旧的 Label Studio 共享登录、直接裸 iframe 或独立学生账号描述。文档不得把“代码支持某厂商”写成“现场已经连通该厂商”。

## 9. 发布包

发布包至少包含源代码提交号、依赖锁文件、环境变量模板、脱敏配置示例、启动/停止/体检脚本、数据库与内容版本说明、黄金演示账号准备说明、证据包索引和回滚说明。真实密钥、个人数据、录屏原件和本地调试目录不得进入仓库。

## 10. 完成定义

全量门禁通过、目标电脑连续三次演示成功、性能预算有测量记录、降级场景可控、文档与实际一致且无敏感信息，才算发布就绪。只通过单元测试或本机手工跑通一次不算完成。
