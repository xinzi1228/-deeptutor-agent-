# 标注星图竞赛就绪纵向优化总设计

日期：2026-08-13

状态：已批准，作为本轮竞赛纵向优化总设计基线

适用项目：标注星图（DeepTutor Agent）

## 1. 背景与结论

项目已经具备多学习档案、教学对话、数据标注、Label Studio 专业模式、标注教练、学习报告、可视化作品、能力中心和扩展市场等基础能力。当前主要风险不是功能数量不足，而是专业内容可信度、学生主线复杂、跨页面状态割裂、自研标注交互不足、模型调用链过长、设置与权限混杂，以及缺少可复现的真实用户验证。

本轮采用“纵向闭环治理”，沿着学生真实路径逐段优化，不更换 Next.js、FastAPI 和 Label Studio，不引入 Redis、消息队列或微服务，不进行全站重写。第一阶段以普通竞赛电脑为最终验收环境，以用户感知速度和完整学习闭环为主要指标。

## 2. 目标与成功标准

### 2.1 核心用户路径

```text
登录或选择学习档案
→ 学习首页
→ 主对话与入门诊断
→ 当前学习任务
→ 教学标注或专业标注
→ 标注教练反馈
→ 提交、评分与订正
→ 成长报告与下一任务
```

### 2.2 性能目标

以 4 核 CPU、8 GB 内存、无独立显卡、Chrome 或 Edge、普通校园网络的竞赛电脑为基准：

- 冷启动 3 秒内达到可操作状态；
- 页面切换 1 秒内出现核心内容；
- 成长页 2 秒内展示关键首屏数据；
- 点击发送后 300 毫秒内展示真实处理状态；
- 模型服务正常时 5 秒内开始输出；
- 模型服务异常时 5 秒内给出明确阶段或故障状态；
- 核心答案优先在 15 秒内完成；
- 超过 30 秒的任务必须允许取消或重试；
- 学生闭环中不得出现重复写入、跨档案串数据和任务状态丢失。

### 2.3 竞赛目标

- 专业结论、题目、评分规则和阈值可追溯；
- 固定交通道路目标检测的 5 至 7 分钟黄金演示闭环；
- 完成 2 名学生和 1 名职教教师的优化前后对照测试；
- 自动生成不伪造数据的匿名竞赛验证证据包；
- 学生首屏不再暴露模型、Embedding、MCP、Skill 和服务地址等管理概念。

## 3. 范围与非目标

### 3.1 本轮范围

1. 学生闭环的架构与性能治理；
2. 学生端信息架构、布局和连续体验；
3. 专业内容、教材、题库和来源治理；
4. 矩形框教学标注与 Label Studio 同步；
5. 标注教练上下文、评分和订正；
6. 大模型渐进回答、可信引用、混合检索和评测；
7. 学生、教师、管理员权限与工作台重组；
8. 真实用户测试和竞赛证据生成。

### 3.2 非目标

- 不全面重构所有页面和全部标注模态；
- 不拆微服务，不新增 Redis 或消息队列；
- 不维护 Label Studio 前端源码分叉；
- 不在竞赛前建设任意第三方扩展自由安装能力；
- 不让 AI 自动发布教材内容、题目或评分规则；
- 不以模拟回答冒充外部模型的实时回答。

## 4. 总体架构

### 4.1 统一当前学习任务

后端建立唯一的 `CurrentLearningTask` 业务对象，至少包含：

- 账号、学习档案和权限上下文；
- 场景、课程、知识点、任务及版本；
- 当前阶段和允许的下一步；
- 教学模式或专业模式的编辑权；
- 标注草稿、正式提交和最近评分引用；
- 教练会话、相关记忆和历史错误引用；
- 计时、同步状态和内容版本。

学习首页、主对话、教学标注台、专业模式、标注教练和成长页均读取同一对象。阶段转换由后端用确定性规则控制，大模型负责解释与教学表达，不负责决定是否必须记录或推进阶段。

### 4.2 聚合接口与渐进加载

为学习首页和成长页分别提供首屏聚合接口。首屏只返回继续学习所需的信息，图谱、复杂图表、历史记录和高级功能按需加载。切换档案时取消旧请求、清除旧缓存并校验档案版本，旧响应不得覆盖新档案状态。

### 4.3 缓存抽象

第一阶段使用进程内和浏览器本地缓存，但通过统一接口封装。缓存键必须包含账号、学习档案、数据类型和版本。提交标注、完成测验、切换档案和内容版本更新时进行精确失效。未来需要多实例部署时可替换为 Redis，而不修改页面与业务接口。

### 4.4 渐进拆分代码

仅拆分本轮涉及的巨型文件，目标边界为：

- 页面容器：路由与页面组合；
- 数据层：请求、缓存、取消和档案隔离；
- 业务层：当前任务、阶段转换、权限和评分；
- 展示层：卡片、对话、图表和标注界面；
- 集成层：模型、知识库与 Label Studio 网关。

每次迁移一个明确能力，保留临时适配层并完成回归后再继续，不进行一次性重写。

## 5. 学生端页面与连续体验

### 5.1 一级导航

学生仅保留四个一级入口：

- 学习：当前任务、对话、讲解和继续学习；
- 实训：教学标注、Label Studio 专业模式和标注教练；
- 成长：报告、薄弱点、错题和待处理问题；
- 我的：档案、PIN、回答详细度、字体、主题、语音、提醒和退出。

模型、Embedding、知识库索引、MCP、Skill、Agent、服务体检和密钥管理不向学生展示。

### 5.2 学习首页

首屏只回答“正在学什么、现在做什么、最近哪里需要提高”。默认展示继续学习主按钮、当前任务、一个薄弱点和最近成果。历史课程、知识图谱和详细分析在二级区域展开。

### 5.3 主对话

输入区默认保留输入、发送、附件和语音。回答采用渐进披露：一句结论、当前操作、关键原因、可展开详情和引用/可视化。模型、知识库和 Agent 选择不常驻学生输入区。

### 5.4 实训与成长

实训明确区分“教学模式”和“专业模式”，但共享任务、草稿、教练、记忆和成绩。成长页首屏只展示一个核心掌握指标、一个薄弱点、一个下一任务和最近报告。插件管理、记忆整理等技术操作迁出成长页。

### 5.5 连续性

四个学生入口共享当前学习任务迷你状态条。页面切换恢复未提交输入、标注草稿、计时和合理的滚动位置。切换学习档案后不得保留上一档案的草稿、教练消息或报告缓存。

## 6. 专业内容与教材治理

### 6.1 内容治理工作台

管理员工作台设置待导入教材、待审核知识、待审核题目、标准冲突、低质量解析、已发布版本和历史影响队列。现有 60 篇资料与 102 道题一并纳入审核。AI 只做初审和修改建议，管理员完成最终审核与发布。

### 6.2 来源模型

每条知识、题目、答案和评分规则保存：

- 来源类型和可信等级；
- 标准号，或教材的书名、ISBN、版次和出版社；
- 章节、页码和原文定位；
- 官方链接或原文件哈希；
- 摘要、内容版本、审核人和审核时间。

来源等级依次为国家标准及正式文件、正式出版教材和实训手册、官方工具文档、高质量论文或可靠开源资料、项目经验建议。经验规则可以用于教学，但必须标明为建议或示例阈值，不得冒充国家标准。

### 6.3 教材导入中间层

管理员可导入 PDF、Word、PPT 和图片。确定性程序先完成文件识别、OCR、版面分析、表格与图片提取，再转换为保留章节、原页码、幻灯片编号、资源引用和文件哈希的结构化 Markdown。原文件永久保留，Markdown 是可重建的中间层。

### 6.4 教材解析子 Agent

教材解析子 Agent 只读取结构化 Markdown，负责提取术语、知识点、操作步骤、安全规范，生成教学摘要、引用卡片、候选题和标准冲突报告。它不能修改原文件，不能自动发布，不能直接更新正式题库或学生成绩。

低质量扫描、错位表格、公式失败或页码不明的结果必须进入人工复核队列，并展示原页、识别文本和问题位置。与现行标准冲突时保留教材原意，标记旧版本或待确认，不自动改写教材。

### 6.5 版本与重新评估

知识、题目和评分规则的修改发布新版本，不覆盖旧记录。系统保留原始答题和初次成绩，标记受影响记录并重新生成掌握度与报告。学生可看到“课程规则已更新”的说明。

## 7. 标注实训与 Label Studio

### 7.1 数据事实分工

- 标注星图管理课程、步骤、档案、记忆、评分规则、成绩和报告；
- Label Studio 管理专业任务、正式标注结果和标注修订版本；
- 教学台和专业模式统一通过后端网关读取和提交标注数据；
- 不在两个前端之间直接复制正式数据。

### 7.2 草稿、编辑权与同步

画框后立即保存浏览器本地草稿，并定时通过网关保存后端草稿。只有正式提交才生成 Label Studio 正式标注版本并进入评分。

同一道题同一时间只有教学模式或专业模式之一拥有编辑权。切换模式时保存草稿、释放编辑权并继承任务、标签、草稿、步骤、教练会话、当前档案记忆、历史错误和计时状态。

本地草稿按账号、档案和任务隔离。同步失败时允许继续编辑并明确显示“暂存于本机，尚未同步”；切换模式和正式提交前必须同步成功。

### 7.3 矩形框第一阶段能力

- 先选择类别再画框；
- 选中、移动、缩放、删除和修改标签；
- 画布缩放和平移；
- 对象列表；
- 撤销、重做和常用快捷键；
- 越界、重复框、明显漏标和标签错误的即时规则检查。

其他标注类型保持现有能力，不在第一阶段平均铺开重构。

### 7.4 标注教练

标注教练由标注星图以可展开悬浮侧栏嵌入专业模式，不修改 Label Studio 源码。学生提问时读取任务、已保存草稿、当前步骤、当前档案记忆和历史错误。

专业模式通过轻量事件桥接提供当前工具、标签、框数量和选中对象；完整坐标以网关保存结果为准。本地确定性规则优先处理明确错误，只有需要解释时调用模型。长时间停顿或明显错误仅触发一次轻量提醒。

### 7.5 评分与订正

框位置、类别、漏标、重复框和越界由版本化的确定性算法评分，大模型只负责教学化解释。保存规则版本、参考答案版本和计算明细。第一次提交与订正版本均保留，成长报告展示改正内容与剩余薄弱点。

### 7.6 Label Studio 不可用

教学模式可继续使用本地草稿、本地规则检查和课程资料，但不能正式提交或生成最终成绩。恢复后通过网关同步，不创建第二套正式标注事实来源。

## 8. 大模型输出、知识库与可信可视化

### 8.1 回答协议

默认顺序为一句话结论、当前操作、关键原因、可展开讲解、引用与可视化。理论问题、标注求助、错误反馈和学习报告使用独立响应合同。学生可选择简洁、标准或详细风格。

### 8.2 执行状态和时间预算

发送后立即显示由真实执行阶段驱动的状态：理解问题、检索资料、结合任务、组织回答。超过 15 秒显示继续等待、取消和重试；取消必须同时停止前端流和后端任务。

按意图设置工具预算：普通理论问答最多一次检索；标注求助读取任务、草稿和最多一次检索；学习报告使用聚合数据；只有明确需要时才调用图表、图解或生图子 Agent。超出预算的扩展任务异步执行，并追加到原回答。

### 8.3 统一混合检索

内置资料、标准、管理员导入教材和官方文档进入统一入口。关键词检索处理标准号、术语和精确章节，语义检索处理大白话问题，最终根据来源等级、课程范围、审核状态和版本重排。

Embedding 必须依次通过连接、小样本索引、检索质量、引用定位和权限隔离测试后由管理员启用。切换模型时创建新索引版本，验收后切换，旧版本保留到新索引稳定。

### 8.4 引用与不确定性

学生默认看到来源名称、章节或页码和可信等级的引用卡片，展开后查看必要原文摘要与定位。管理员可查看文件哈希、版本和审核记录。无可靠来源时必须明确说明；国家标准、安全规范、评分规则和阈值不得使用模型常识生成确定结论。

模型或互联网检索产生的新知识与候选题只能进入待审核区，不能直接成为正式课程或评分依据。

### 8.5 可信可视化

数值图表必须绑定服务端数据集 ID、记录版本、查询条件、单位和哈希。模型只能选择图形并生成说明，不能自行填写统计数字。流程图和概念图可由模型组织，但不得混入虚构成绩或趋势。正文先输出，可视化异步追加到同一回答。

## 9. 角色、权限与工作台

### 9.1 权限模型

账号角色控制系统功能，档案授权控制对具体学生的只读、代管或不可访问权限。所有权限由后端强制执行，前端隐藏不能代替授权校验。

### 9.2 教师工作台与代管

教师可查看被分配学生、只读记录、任务、报告、待处理问题、教学审核建议和测试记录。需要写入时填写理由进入按次授权的 30 分钟代管模式；无操作 30 分钟后自动恢复只读。

代管只允许分配任务、整理待处理问题、添加教师反馈和修正经审核的学习记录。禁止删除原始对话、原始标注、初次成绩和修改 PIN。每次写操作保存教师、理由、时间及修改前后差异。

### 9.3 管理员工作台

现有能力中心和设置合并为一个管理员工作台，按任务分为内容治理、教学配置、AI 能力、扩展与集成、系统运维。首页展示健康状态、待审核项、失败任务和初始化进度。旧入口在迁移期跳转到新位置。

### 9.4 初始化与扩展安全

初始化向导可跳过、可恢复，顺序为账号安全、对话模型、Embedding、知识库、Label Studio 和完整体检。生图、MCP、Skill 与高级模型为可选项。

扩展采用白名单市场和管理员审批，安装前显示读取、写入、网络和执行权限，再分配给教师或课程。学生不能安装任意扩展。开发模式可以导入未审核扩展，但默认禁用、明确警告并与竞赛环境隔离。

### 9.5 密钥与高风险变更

密钥保存在系统密钥库或环境变量中，业务数据只保存引用。界面仅显示掩码，连接测试、日志和诊断报告自动脱敏。已经暴露过的密钥必须轮换。

发布知识、修改评分规则和启用未审核插件需要二次确认、版本记录和回滚。第一阶段不强制双管理员审批，正式学校部署时可配置启用。

## 10. 错误处理与受控降级

错误统一分为：

- 可重试：网络、模型超时、检索失败；
- 可继续：可视化失败但正文可用；
- 必须处理：档案失效、权限不足、版本冲突；
- 降级运行：外部模型或 Label Studio 不可用，但本地学习能力仍可继续。

学生提示必须说明发生了什么、内容是否保存和下一步操作。详细错误与脱敏诊断仅对管理员展示。提交标注和测验使用幂等键，重复点击不得重复写入。

## 11. 观测、评测与真实用户验证

### 11.1 匿名性能观测

本地记录页面可操作时间、接口耗时、首个状态与首字时间、工具调用次数、取消、超时和错误类型。不记录对话正文、标注内容、密钥和身份信息。

### 11.2 自动测试

1. 单元测试：缓存失效、档案隔离、任务阶段、评分版本；
2. 接口测试：聚合接口、取消、超时、幂等和权限；
3. 组件测试：骨架屏、错误提示、阶段状态和模式切换；
4. 端到端测试：档案到成长报告的完整闭环；
5. Label Studio 契约测试：任务读取、草稿、正式提交和版本兼容；
6. 内容测试：引用定位、审核状态、来源等级和历史重新评估。

### 11.3 大模型评测集

建立 30 至 50 条真实案例，覆盖新手理论、模糊需求、标注卡住、错误订正、引用追溯、无可靠来源、报告、可信图表、超时降级和跨档案隔离。交通道路场景约占三分之一，其余覆盖工厂、校园和商超。

程序检查时间、工具预算、引用、数据集 ID、权限和禁止项；教师或学生评价准确性、易懂程度与教学帮助。评分模型只能提出建议，不能替代人工专业终审。

### 11.4 真实用户测试

使用 2 名学生和 1 名职教教师，采用匿名编号与知情同意。录屏、录音和原话引用分别授权，可申请删除个人材料。

同一批用户完成优化前和优化后两轮固定任务；第二轮使用难度相同但图片不同的交通道路目标检测素材。记录完成率、耗时、卡住次数、错误数、主观评分和十分钟访谈。系统基于真实记录生成证据包、对比图和原始记录索引，不得补写缺失数据；人工修改结论需保留记录。

## 12. 黄金演示闭环

固定使用交通道路目标检测：

```text
三题入门诊断
→ 遮挡和贴边知识讲解
→ 车辆与行人矩形框标注
→ 确定性质检与评分
→ 标注教练解释
→ 学生订正
→ 成长报告和下一任务
```

演示目标为 5 至 7 分钟。其他场景只展示为可扩展能力，不进入主演示路径。网络或模型异常时启用明确的受控降级，不使用预设 AI 回答冒充实时结果。

## 13. 实施阶段与验收门

### 阶段一：安全、基线与专业纠错

- 轮换已暴露密钥并迁移密钥存储；
- 建立性能和错误基线；
- 修正错误标准引用；
- 将现有资料与题库纳入来源和审核模型。

验收门：无已知明文密钥；错误标准不再作为数据标注规程；基线可重复测量。

### 阶段二：统一任务与学生首屏

- 建立 `CurrentLearningTask`；
- 学生四入口和当前任务状态条；
- 首页与成长首屏聚合接口；
- 档案隔离、缓存、取消和骨架屏。

验收门：达到页面时间预算，跨档案无串数据，核心页面不暴露管理员配置。

### 阶段三：矩形框闭环与专业模式

- 完成矩形框编辑能力；
- 草稿、单一编辑权和 Label Studio 网关同步；
- 教练上下文、确定性评分和订正版本；
- Label Studio 降级与契约测试。

验收门：教学模式和专业模式使用同一正式结果，离线草稿不丢失，完整提交可追溯。

### 阶段四：可信 AI 与知识库

- 渐进回答、执行状态、取消和工具预算；
- 结构化 Markdown 教材导入与解析子 Agent；
- 混合检索、引用卡片和 Embedding 验收；
- 可信图表和 30 至 50 条评测集。

验收门：无来源时不编造规范；数值图表均绑定可信数据；核心回答满足时间预算。

### 阶段五：角色工作台与竞赛证据

- 教师、管理员后端权限和代管审计；
- 管理员五中心与初始化向导；
- 扩展白名单和高风险变更机制；
- 优化前后真实用户测试、黄金演示和竞赛证据包。

验收门：权限越权测试通过；三名真实用户完成两轮测试；竞赛证据可追溯到原始记录。

## 14. 关键风险与控制

| 风险 | 控制措施 |
|---|---|
| 范围过大 | 严格按阶段和验收门推进，不并行重构全部模态 |
| 专业内容二次误改 | AI 初审、管理员终审、版本化发布 |
| Label Studio 升级破坏集成 | 只使用网关与轻量事件桥接，持续运行契约测试 |
| 性能优化造成串档 | 所有缓存和请求绑定档案与版本，切档取消旧请求 |
| 模型输出不稳定 | 确定性状态机、调用预算、引用边界和自动评测 |
| 现场网络失败 | 本地草稿、规则检查、课程资料和明确受控降级 |
| 教材版权风险 | 原文件权限控制，仅展示必要摘录，不默认公开下载 |
| 管理入口再次复杂化 | 以管理任务组织五个中心，首页仅呈现健康与待办 |

## 15. 最终完成定义

只有同时满足以下条件，本轮优化才算完成：

1. 学生核心闭环达到性能预算并通过端到端测试；
2. 学习、实训、教练和成长共享同一当前任务；
3. 交通道路矩形框任务可以完成教学、专业标注、评分和订正；
4. 专业结论和题目可追溯，错误标准已完成审校；
5. 大模型回答遵守调用、时间、引用和可信数据规则；
6. 学生、教师、管理员权限由后端强制执行；
7. 三名真实用户完成优化前后测试并形成证据包；
8. 黄金演示在竞赛电脑上可于 5 至 7 分钟稳定完成。
