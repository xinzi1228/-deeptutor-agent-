# 角色工作台、初始化向导与白名单扩展设计

日期：2026-08-14

状态：已批准，待实现
对应任务：竞赛纵向优化 4.2、4.3

## 1. 目标

让学生只看到学习所需功能，让教师围绕学生与任务工作，让管理员在一个工作台完成内容、教学、AI、扩展和运维配置。首次部署通过可恢复向导完成必要能力配置；Skill、MCP 与学习插件统一进入受控目录。

## 2. 三类工作区

### 2.1 学生工作区

一级入口保持“学习、实训、成长、我的”。模型、Embedding、知识库引擎、MCP、Skill、服务地址、密钥和运行日志不出现在学生页面。学生只看到课程赋予的能力名称与用途，例如“生成学习图解”，不看到内部协议。

### 2.2 教师工作台

仅显示被分配学生及教学任务：学生概览、待处理问题、任务分配、报告、教师反馈、内容审核建议和用户测试记录。默认只读；进入代管时固定显示身份、理由和剩余时间，禁止伪装成普通学生界面。

### 2.3 管理员五中心

1. 内容治理：教材导入、转换任务、知识条目、题库、引用、版本、审核与发布。
2. 教学配置：课程、场景、能力图谱、任务分配、评分规则和教师授权。
3. AI 能力：对话、Embedding、生图模型，连接测试、用量与评测。
4. 扩展与集成：Skill、MCP、学习插件、Label Studio、权限与健康状态。
5. 系统运维：账号角色、备份、审计、体检、失败任务、性能和脱敏诊断。

管理员首页优先展示待审核、失败任务、服务健康、初始化进度和高风险提醒，不堆满配置表单。旧设置和能力中心 URL 保留兼容跳转。

## 3. 页面结构和体验规则

- 每个中心首屏先说明“现在是否可用、有什么待处理、下一步是什么”。
- 基础设置与高级设置分层；密钥输入、原始 JSON 和调试日志默认折叠。
- 配置保存后显示影响范围和测试结果，不只提示“成功”。
- 长任务进入统一任务中心，显示排队、运行、失败、重试和完成，不要求用户停留页面。
- 教材导入支持 PDF/DOCX/PPTX/图片先转 Markdown，再由教材解析子 Agent 生成候选内容；管理员可导入教材，教师仅在授权时提交资料。
- 内容发布、评分规则变更和未审核扩展启用必须二次确认并保留版本和回滚记录。

## 4. 初始化向导

向导顺序固定：

1. 账号安全：管理员密码、密钥存储和备份位置。
2. 对话模型：选择模板、录入密钥引用、连接和最小问答测试。
3. Embedding：连接、中文样例、五项验收。
4. 知识库：创建默认库、导入样例、索引、引用问答验收。
5. Label Studio：管理员连接、项目映射、任务读写契约测试。
6. 完整体检：汇总必需项、可选项、风险和脱敏报告。

生图、MCP、Skill 和高级模型为可选步骤。每一步保存持久状态，可跳过、恢复、重测；重启后从最后未完成项继续。步骤状态为 `not_started/running/passed/failed/skipped/stale`，依赖配置发生变化后相关结果自动变为 `stale`。

向导不得用 Mock 成功代替真实连接。竞赛模式下核心必需项未通过时显示受限状态和降级能力，但允许管理员进入系统修复。

## 5. 统一扩展目录

Skill、MCP 和学习插件使用统一目录模型：标识、类型、名称、版本、来源、校验和、权限清单、网络域名、适用角色/课程、健康状态、审核状态、安装记录和更新策略。

运行门包括：

```text
已安装
AND 已审核
AND 管理员启用
AND 已分配给角色或课程
AND 当前健康
AND 请求权限在清单内
```

学生只能启用/停用已分配能力，不能创建自由文本 Skill、从 Hub 强制导入、使用 `allow_unverified`，也不能直接执行任意注册工具。Skill 自建、Hub 导入、MCP 安装、工具 playground 和权限升级均为管理员操作。

竞赛配置只加载固定白名单与锁定版本。开发模式可以导入未审核扩展，但默认禁用、显著警告，数据与竞赛配置隔离。插件不可借助 Agent 工具绕过授权或档案隔离。

## 6. 模型与密钥

内置 provider 模板负责字段说明、默认端点和测试策略。密钥保存在环境变量或系统密钥库，数据库仅保存引用；页面显示掩码，日志、体检和导出自动脱敏。生图模型是否可用以真实生成测试为准，不能只依据保存配置成功。

## 7. 路由与兼容

新增管理员五中心和教师首页；旧 `/settings`、`/capabilities` 及历史深链按映射跳到新位置，并显示一次迁移提示。直接访问越权 URL 返回明确的 403 页面，不跳到看似空白的配置页。

前端权限用于导航与体验，真实授权由后端统一策略执行。管理员 API 不能只检查“已登录”。

## 8. 验收

自动测试覆盖：三种角色的信息架构、旧路由跳转、直接 URL 越权、向导中断恢复、依赖变更后 stale、真实测试结果记录、学生不能创建/导入/任意执行扩展、白名单分配、撤销后立即失效、开发与竞赛配置隔离。

```powershell
python -m pytest tests/api/test_onboarding_resume.py tests/security/test_extension_marketplace_policy.py -q
cd web
node --test tests/admin-information-architecture.test.ts tests/capability-access.test.ts tests/onboarding-resume.test.ts

```

人工验收：新管理员可按向导完成最小可用配置；重启后继续失败步骤；学生页面搜不到技术配置；教师只看到被分配学生；管理员能从首页定位待审核和失败任务；撤销扩展授权后学生立即不可调用。

## 9. 完成定义

只有角色信息架构和后端授权一致、初始化可恢复且不伪造就绪、扩展执行通过统一白名单门、学生端不暴露技术配置，才算完成。把旧设置换皮或只增加一个市场页面不算完成。
