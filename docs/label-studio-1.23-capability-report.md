# Label Studio 1.23.0 接入能力实测报告

## 结论

本项目应采用 **“每个学习档案独立项目 + 标注星图同源白名单网关”**，不能把 Label Studio 社区版的组织成员权限当作学生数据隔离机制。

专业模式继续保留，但学生只能通过标注星图进入被分配的项目和任务；Label Studio 项目列表、组织管理、用户管理等页面只向管理员开放。同源网关和隐藏会话桥已于 2026-08-13 在一次性隔离实例完成端到端验收，学生进入专业模式时可以不再看到第二个登录页。

## 实验范围

- Label Studio：1.23.0 Community
- 实验地址：`http://127.0.0.1:18080`
- 数据目录：系统临时目录中的一次性隔离目录
- 正式目录 `data/label-studio/`：未读取、未写入
- 身份：一个一次性服务账号、两个一次性学生网页身份
- 数据：两个一次性项目、两条一次性任务、两条空标注

可复现脚本为 `scripts/label_studio_capability_probe.py`，详细脱敏结果为 `docs/label-studio-1.23-probe-result.json`。

## 同源网关端到端复验（2026-08-13）

可复现脚本为 `scripts/label_studio_gateway_e2e.py`，脱敏结果为 `docs/label-studio-gateway-e2e-result.json`。脚本每次新建系统临时目录与独立 Label Studio 数据库，结束后关闭进程树；项目正式 `data/label-studio/` 未被读取或写入。

| 验收项 | 结果 |
|---|---|
| 标注星图档案进入专业工作台，无第二次登录 | 通过 |
| 网关提交 Label Studio 标注并同步回档案记录 | 通过 |
| 两个学习档案使用不同项目，互访项目或任务返回 403 | 通过 |
| 教师只读视角写教学记录或代理提交标注返回 403 | 通过 |

本机桌面版还增加了安全的凭据自动发现：仅当 `LABEL_STUDIO_URL` 为环回地址时，后端才以 SQLite 只读模式发现本机服务 Token，并在私有设置目录生成桥接密钥。远程地址必须显式配置环境变量，避免误读或复用本机凭据。

## 能力矩阵

| 能力 | 结果 | 证据 | 对项目的影响 |
|---|---|---|---|
| 健康与版本接口 | 支持 | `/health`、`/api/version/` 返回 200 | 可做启动检查和版本提示 |
| 服务 Token | 支持 | `/api/current-user/whoami` 返回 200 | Token 仅保留在标注星图后端 |
| 创建项目与导入任务 | 支持 | 两个项目均 201，任务导入 201 | 可把自建题库同步到专业模式 |
| 官方用户创建 API | 受限 | 可创建组织用户，但序列化器不接收密码 | 不能仅靠公开 API 创建可登录的隐藏身份 |
| 网页会话 | 受限 | 两个注册会话均建立成功并直达任务 | 需要同源反向代理与服务端会话桥，不能依赖跨源 iframe |
| 标注人追溯 | 支持 | 两个会话提交均 201，`completed_by` 不同 | 可以把专业标注归属到具体学习档案 |
| 学生项目隔离 | 不支持 | 身份 B 的项目列表包含 A 项目，直接访问 A 项目返回 200 | 必须由标注星图网关执行项目/任务白名单 |
| iframe 响应头 | 初步支持 | 未发现阻断 iframe 的 X-Frame-Options/CSP | 仍需在最终同源地址做浏览器 Cookie/退出 E2E |

## 为什么不能直接“去掉 Label Studio 账号系统”

Label Studio 的网页标注仍依赖自己的 Django 会话和用户对象，标注记录中的 `completed_by` 也来源于该用户。若所有学生共用一个 Label Studio 网页账号，虽然表面上只登录一次，但会造成三类问题：

1. 所有学生在 Label Studio 中成为同一个标注人，无法追溯个人学习过程；
2. 社区版按组织展示项目，共用身份会看到全部项目；
3. 标注星图退出后，Label Studio 会话可能仍然有效。

正确做法不是修改 Label Studio 认证源码，而是由标注星图维护“学习档案 → 隐藏 Label Studio 身份/独立项目”的映射，学生浏览器只与同源网关交互。账号细节、密码和 Token 均不展示给学生。

## 后续实现约束

1. 后端保存服务 Token；浏览器永不接收 Token、隐藏身份密码或 Cookie 明文。
2. 每次进入专业模式，先校验当前 `learning_profile_id` 是否拥有目标项目和任务。
3. 网关拒绝项目列表、组织、用户、导入、导出和未分配任务路径。
4. Label Studio 不可用时，教学模式和草稿记录继续可用。
5. 标注星图退出或切换学习档案时，同时撤销专业模式授权。
6. 同源会话、CSRF、直接改项目/任务 URL 已覆盖；生产上线前仍需在最终 HTTPS 域名复验 Cookie Secure/SameSite、退出和刷新行为。

## 决策门

Phase 0 与隔离网关 E2E 均通过，受控网关方案可以进入目标用户验收：

- 继续实施多学习档案和专业标注模式；
- 不采用所有学生共用 Label Studio 网页身份；
- 不向学生暴露 Label Studio 管理页面；
- 学生可见的第二次登录已经由同源会话桥移除；不得改回直连 Label Studio 登录页。
