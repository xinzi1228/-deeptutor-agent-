# 我们给 DeepTutor 加的每一个新功能（详细版）

> 这份文档按**开发顺序**，把每一次加的新功能都讲清楚——它是什么、怎么触发、你（学生/老师）能感觉到什么、在界面上哪里看。
> 通俗版：`docs/fork-features-simple.md`（5 分钟概览）｜技术版：`docs/fork-features.md`（代码定位）
> 一句话总结：**我们把这个通用 AI 助教，变成了一所「数据标注培训学校」——有智能老师、有作业、有成绩单、有毕业标准，还能记住每个学生的进步。**

---

## 第 1 次加：数据标注教学智能体（第一个大版本）

**这所学校的地基。** 给 DeepTutor 装上了"标注教练"这个角色 + 4 样核心工具。

### ① 标注教练（annotation-coach 角色）

- **是什么**：一个专门的 AI 老师人设，被设定为"诊断优先的苏格拉底教练"——不急着教，先弄清学生为什么错。
- **你感受到的**：跟它对话，它不会直接念讲义，而是会追问"你为什么会这么想？"引导你自己想明白。
- **在哪看**：对话页面（Home）选择 **annotation-coach** persona。

### ② IOU/F1 检查工具（打分老师）

- **是什么**：一个"自动改作业"的评分器。学生画完框，它算出综合分数（F1）、精确率、召回率，还能逐条告诉你哪个框对、哪个框多画了、哪个漏标了。
- **你感受到的**：交作业立刻知道分数和错在哪，不用等老师人工批改。
- **在哪看**：没有独立界面——是老师在对话里调用的"阅卷工具"。

### ③ Canvas 标注工作台（做作业的地方）

- **是什么**：一个在浏览器里画框标注的小工具，内置 8 个真实任务（找车、找马、动物分类等），带难度分级。
- **你感受到的**：学生拖鼠标画框、选标签（车/马/非车）、点"检查标注"立即出分，还有"撤销/清除"。分类任务还能调"信心值"滑块。
- **在哪看**：侧边栏 **Annotation** → 基础模式。
- **问Coach 闭环**：标注完点"问Coach：帮我分析"→ 自动跳转聊天页，把结果发给老师分析。

### ④ Label Studio 集成（工业级工具）

- **是什么**：接入了真正的工业标注软件 Label Studio（对标"学了就能上岗"）。
- **在哪看**：侧边栏 **Annotation** → 专业模式（已启动，http://localhost:8080）。

### ⑤ 记忆追踪（学生小本本）

- **是什么**：把学生的偏好、学过什么、做到哪了记下来，下次对话能续上。
- **在哪看**：侧边栏 **Memory**。

### ⑥ 诊断式教学（先当"医生"再当"老师"）

- **是什么**：教练第一次见面不当老师先当医生——通过 2-3 轮**自然聊天**摸清学生底子（不填问卷），判定教学模式，再决定教什么。
- **怎么判定**：完全零基础 → **Zero-Base**（从定义教起）；听过没做过 → **Standard**；做过多种还能说清困惑 → **Advanced**（直接上难度摸底）。
- **你感受到的**：老师问"你学标注是为了什么？之前接触过吗？"像聊天，不像考试。
- **产出**：诊断记录 + 教学模式 + 学习路线。

## 第 2 次加：学习记录 + 个人中心（成绩单上线）

- **是什么**：给每个教学里程碑做**永久存档**——诊断完记一条、知识点掌握记一条、任务评测完记一条，全部落盘成"学习记录"；同时在记忆里镜像一行摘要，下次对话老师能"断点续学"。
- **记录什么**：`data/user/workspace/learning/records.jsonl`，每条含类型（诊断/理论掌握/标注练习）、任务、知识点、F1、readiness（能否过关）、错误模式等。
- **你感受到的**：第二次打开对话说"继续上次学习"，老师记得你上次学到 task2、F1 多少。
- **在哪看**：侧边栏 **Progress** 个人中心——雷达图、F1 曲线、技能树、时间线一整套仪表盘（第 3 次加会细说）。

## 第 3 次加：开源智能体借鉴 · 第一部分（教学更严谨）

### ① 前置依赖链（先学地基再学楼）

- **是什么**：29 个标注技能标好了先后顺序（比如"先学会画框规范，才能学遮挡目标处理"）。
- **你感受到的**：老师不会让你跳级，没打地基的技能不会硬推。
- **在哪看**：Progress → **能力图谱**（技能树显示依赖）。

### ② 教育学自检（教学不出错）

- **是什么**：给老师定了 3 条教学铁律：诊断阶段绝不教新概念、绝不问卷式提问（要聊天式摸底）、摸底控制在 1-2 题 3 分钟内。
- **你感受到的**：老师跟你聊天摸底，而不是甩你一张试卷。

### ③ 有界诊断 brief（诊断只记重点）

- **是什么**：诊断完只存 4 个关键信息 `{学习目标, 目标类型, 水平, 教学模式}`，不存冗长画像。
- **为什么**：够用就行——下次会话靠这 4 条恢复路线，不用重新诊断。
- **在哪看**：数据文件 `brief.json`。

### ④ 课程范围 RAG（讲课时只查当前模块）

- **是什么**：老师讲理论查知识库时，只查"当前模块"的内容，不漫无目的搜。
- **你感受到的**：讲 IOU 就查 IOU 相关，不会扯到无关的东西。

## 第 4 次加：学习者状态 MCP 接口（给外部 AI 用）

- **是什么**：开了一个"标准插座"（MCP 协议），让外部 AI 程序（比如 Claude Code）也能查学生学习情况：总览、雷达、技能树、任务库、IOU 评测、学习记录等。
- **产出**：19~21 个查询/写入工具 + 7 个资源。
- **谁用**：开发/演示时给外部智能体调用，普通学生用不到。
- **验证**：✅ 已预跑，外部可查。

## 第 5 次加：可重跑建课（课程计划像公式一样确定）

- **是什么**：同一份诊断结果，每次生成课程计划都得到**一模一样**的结果（可复现），且写入是原子操作（断电不留半成品）。
- **4 个模块**：标注基础 → 进阶技能 → 质量管控 → 工具进阶，每个模块有目标和 F1 达标线。
- **依赖图**：自动从技能树抽取出"技能 ← 前置技能"的关系表（DAG）。
- **在哪看**：Progress → **课程计划**卡片（模块列表）；数据在 `course_plan.json`。

## 第 6 次加：IOU 交互演示工具（把抽象讲直观）

- **是什么**：一个可交互的 HTML 页面——两个框（蓝=你画的，绿=标准答案）能**拖动、缩放**，IOU 数值实时刷新，颜色分级（≥0.5 绿/一般黄/差红），带 3 个引导思考题。
- **你感受到的**：老师讲"重叠度"时，你能亲手拖框看数值变化，比死记公式直观得多。
- **在哪看**：老师对话里调 `generate_iou_demo`，返回的链接打开即演示。✅ 已生成 `iou_demo.html`。

## 第 7 次加：决策审计（老师为什么这么教，有据可查）

- **是什么**：老师每做一次"推荐任务 / 判定能否过关 / 选路线"，都必须记一句**"决定了什么 + 为什么"**，写进审计日志。
- **记录**：`{类型, 目标, 理由, 证据?, 时间}`——比如"推荐 task1，理由：入门任务适合先巩固画框规范"。
- **在哪看**：Progress → **最近教学决策**面板。
- **为什么**：让每条教学建议都能追溯回证据，防止"老师拍脑袋"。

## 第 8 次加：对抗性教学评估（给老师配个"挑刺的督学"）

- **是什么**：老师设计好教学方案后，系统用**第二个独立 AI 身份**（专门的严格人设）从 6 个维度审查方案：内容太多吗？起点合适吗？理论和实操比例对吗？有评估手段吗？……
- **输出**：`质疑点`（带严重度）+ `修正建议` + `结论`。
- **你感受到的**：像学校有"督学"盯着老师，防止老师"自己看自己全对"。
- **在哪看**：Progress → **教学方案评估**面板。

## 第 10 次加：记忆进化 Reflection（记忆会自己整理）

- **是什么**：学习记录越积越多后，系统自动"整理笔记"：
  - **合并**：同一任务/知识点的重复记录，合并成最新一条
  - **升级**：同一个错误模式出现 ≥2 次 → 标记"已确认"（单次观察永远不升级，防止误判）
  - **归档**：旧记录归档但**永不删除**（可逆）
- **你感受到的**：点 Progress 右上角 **记忆整理** 按钮，统计"合并了几条、归档了几条"。
- **在哪看**：Progress 页记忆整理按钮 / Memory 页。

## 第 11 次加：foresight 预测验证闭环（老师会"预言"了）

- **是什么**：老师每次记学习记录时，**顺手预测学生下一步会卡在哪**（比如"预测你 task2 会漏小目标"）；下次见面先验证上一条预测对不对。
- **命中** → 正向信号（老师懂你）；**没中** → 修正对学生的画像。
- **在哪看**：Progress → 统计卡片显示**预测命中率**；时间线每条记录有"预测命中/未中"徽章。
- **为什么**：让"老师懂不懂学生"自我验证，不靠猜。

## 第 12 次加：episodes 时间线 + 原子事实（记忆更立体）

### ① 学习时间线（像朋友圈动态）

- **是什么**：把所有学习记录按"天"分组倒序排列——某天练了哪个任务、掌握哪个知识点、预测命中没有。
- **在哪看**：Progress → **学习时间线**（蓝=练习/紫=理论/绿=诊断，带 F1 和徽章）。

### ② 原子事实（会了什么，有据可查）

- **是什么**：一份自动提炼的"已确认掌握的知识点清单"——练习 F1≥0.7 或理论掌握（readiness 达标）才算"有证据地会了"。
- **在哪看**：无独立界面，支撑技能树/仪表盘展示；外部 MCP 可查。

## 第 13 次加：教学自改进循环（教学流程自己会进化）

- **是什么**：当同一个学习缺口反复出现、或督学两次指出同一问题时，老师对自己的**教学流程文件**做一次**单点修改**（一次只改一处），并记入带版本号、可回滚的日志。
- **记录**：`{改了哪个流程, 督学原话, 这次改了什么, 版本号}`。
- **在哪看**：Progress → 教练绩效里"教学自改进次数"；数据在 `teaching_changelog.jsonl`。
- **你感受到的**：老师会越教越聪明，但每次只改一点、可回退，不激进。

## 第 14 次加：CRAG 相关性校验 + 学习手册 docx

### ① CRAG 相关性校验（检索先验货）

- **是什么**：老师用知识库检索前，先检查检索结果可不可信（来源分数高不高）。低相关 → 改写查询重试 1 次 → 还不行就明说"知识库没这内容"转查技能手册，**绝不硬编答案**。
- **你感受到的**：老师不会一本正经地胡说八道——查不到就说查不到。

### ② 学习路径手册（下载带走）

- **是什么**：把课程计划导成正式 Word 手册：标题 + 教学目标和计划信息 + 4 个模块各一节（目标/概念顺序/练习任务）+ 技能前置关系表。
- **在哪看**：Progress → 课程计划卡片 → **下载手册**按钮（生成 `.docx` 新窗口打开）。✅ 已验证可下载。

## 第 15 次加：Coach 成功指标 + 角色氛围（给老师也装上 KPI）

### ① 教练绩效指标（6+ 项，全部自动算）

| 指标 | 什么意思 |
|------|---------|
| F1 提升率 | 学生从第一次练习到现在进步了多少 |
| 模式确认率 | 老师确认的错误模式占比（是否谨慎） |
| 预测命中率 | 老师"预言"学生下一步的准不准 |
| 教学自改进次数 | 老师改进过几次教法 |
| 决策审计条数 | 老师记了多少条"为什么" |
| 任务完成数 | 学生练了几个任务 |

- **在哪看**：Progress → **教练绩效**面板。
- **复盘纪律**：老师会话结束会对照指标自查，指标长期停滞 → 触发自改进。

### ② 角色氛围（人设定了调）

- **是什么**：给教练定了视觉人设 `🎯 颜色蓝` + 一句话氛围"诊断优先的苏格拉底教练——先弄清学生为什么错，再决定教什么"，影响所有回复语气。

## 第 16 次加：回归修复（演示时发现的大 bug）

### ① 修复"老师不落盘"（记录全空）

- **bug**：端到端演示发现——老师走完全部流程，但 records/decisions/brief/课程计划**全是空的**（嘴上说了但没存档）。
- **修法**：给老师加第 10 条铁律"每个教学里程碑必须落盘"，并在评分工具、任务工具的结果后面**贴便利贴**：`[必做] 评测完立即记录成绩 + 记决策理由`。
- **效果**：✅ 回归验证——老师评测后自动落盘，records/决策/图谱都有数据。

### ② 修复"诊断完不建课"

- **bug**：诊断结束没有工具生成课程计划。
- **修法**：新增 `finalize_diagnosis` 工具——**一次调用完成两件事**：存诊断 brief + 生成 4 模块课程计划。设为第 11 个常驻教学工具。

## 第 17 次加：知识图谱全套（最后的大功能，技能地图）

### ① 图谱引擎（build + 增量更新）

- **是什么**：把"技能依赖关系 + 学生掌握情况"织成一张持久化的**技能地图**。
  - 节点：技能 / 任务 / 任务组 / 学生
  - 连线：`前置依赖`（技能→前置技能）、`任务需要技能`、`任务属于哪个组`、`已掌握`、`挣扎中`
- **自动维护**：每次记录学习记录 → 图谱自动更新（幂等，最新的算数）；还带"别名映射"让任务知识点名对得上技能规范名。
- **确定性强**：同一份记录重建图谱，结果完全一样。

### ② 风险链查询（risk_path / graph_query）

- **是什么**：老师讲新课前查"这个技能有风险吗"——会告诉你：**缺哪些前置（地基没打）**、**这个技能在挣扎**、**它学不好会连累后面哪个任务**。
- **例子**：查"街景车辆检测"→ 发现"边界框绘制规范"缺失 → 建议先补地基。
- **老师工具**：`graph_query`（第 12 个常驻教学工具），高风险时还自动附一段 LLM 解释，解释失败就退回结构化结果（不阻塞）。
- **在哪看**：对话里老师调用；Progress → **知识图谱·技能风险链**面板（新加的）。

### ③ MCP 暴露 + 前端面板

- **外部**：MCP 客户端可查 `get_knowledge_graph`（节点/边数 + 掌握/挣扎）、`query_risk_path`（风险链）。✅ 已预跑验证。
- **前端**：Progress 页新面板——节点/边数、已掌握（绿）/挣扎中（黄）标签、风险链列表（缺失前置/下游受影响 + 有风险徽章）。

### ④ 别名映射修复

- **问题**：真实任务库的知识点名和技能树名字对不上（比如任务写"多目标检测"，技能树叫"小目标标注策略"），导致某些任务的风险链查不到。
- **修法**：加一张"别名对照表"，让真实数据下所有任务都能算出风险链。✅ 修复后 task4/6/8 都有依赖边。
