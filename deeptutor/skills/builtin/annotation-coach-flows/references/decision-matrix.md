# 决策矩阵

教练在各个环节的分支判断规则。集成 universal-diagnostic-tutor 的 error_to_intervention、readiness_gate、understanding_check 协议。

---

## 1. 形成性评估决策矩阵（理论与实践通用）

每次出题检测后，根据 [正确性 + 自信度] 双维度判断：

| 正确性 | 自信度 | 诊断 | Coach 动作 |
|--------|--------|------|-----------|
| ✅ 正确 | ≥7/10 | **掌握** | 进入 readiness_gate: Advance |
| ✅ 正确 | ≤4/10 | **脆弱** — 可能蒙对的 | 换一种检查方式再测 (understanding_check 选不同 type) |
| ❌ 错误 | ≥7/10 | **误解** — 错误观念根深蒂固 | 认知冲突: 给反例 (error_to_intervention: 过度泛化→反例) |
| ❌ 错误 | ≤4/10 | **未懂** — 完全没理解 | 换方式重新讲 (调 rag 搜不同角度) |

## 2. Error-To-Intervention — 9 种错误→教学干预映射

**来源: universal-diagnostic-tutor / error_to_intervention_protocol.md**

标注领域的适配版：

| # | 错误类型 | 标注领域的典型信号 | 高效干预 |
|---|---------|-----------------|---------|
| 1 | **标记/符号错误** | 把 IOU 公式中的 x,y 和框坐标 x,y 混淆；分不清 xmin/ymin/xmax/ymax | **符号翻译**: "在 IOU 里，(x1,y1) 指重叠区域的角，不是框的角。我们分开来——你要算的是哪几个坐标？" |
| 2 | **概念错误** | 把 IOU 当成比面积；认为"大框=好标注"；认为分类和检测评测方式一样 | **直觉桥接**: "你好像把 IOU 当成比面积大小了。但看——两个框完全不重叠，面积一样大，合理吗？" |
| 3 | **方法选择错误** | 用 IOU 评测分类任务；用 Accuracy 评测目标检测 | **线索对比**: "IOU 测的是位置准确度，适用于检测。分类任务用 Accuracy/F1。你的任务是什么类型？应该用哪个？" |
| 4 | **设置错误** | 坐标格式搞反(VOC vs COCO)；画框时左上角和右下角搞混 | **对象翻译**: "看: VOC 是 (xmin,ymin,xmax,ymax)，COCO 是 (x,y,w,h)。你写的是 COCO 格式但数值像 VOC——重新确认一下。" |
| 5 | **计算错误** | IOU 交集面积算错；F1 公式套错；Precision/Recall 分母用反 | **局部修正 + 检查习惯**: "概念对，公式也对。这一步的减法符号错了。修正后自己验算一次。" |
| 6 | **迁移错误** | task1 的 bbox 技巧在 task2 不会用；换个场景就漏标 | **命名可复用模式 + 近迁移**: "记住: 由大到小扫描是通用技巧。不管什么场景的 bbox 任务——先扫大目标再扫小的。" |
| 7 | **过度泛化** | 把所有深色物体标成 car；把"有四个轮子"的所有东西标成 car | **给反例**: "你把深色物体都标了车。但这张图里的黑色垃圾桶也是深色——它应该标吗？" |
| 8 | **机械记忆不理解** | 公式背对了但解释不了为什么；标准答案记住了但换个问法就错 | **问 why-step**: "计算公式你背对了。但为什么 IOU 的分母是 A+B-交集，不是 A+B？解释一下。" |
| 9 | **空白/无尝试** | 不说话；说"不知道"；空提交 | **渐进提示梯 L0**: "先说说你卡在哪一步？理解概念？不知道怎么画框？还是不确定对不对？" |

**使用规则：**
1. 先诊断错误类型（看学生回答的具体模式，不是看最终对错）
2. 映射到对应干预策略
3. 如果一种干预不奏效，换一种——但 ≤ 3 轮
4. 3 轮后仍不奏效 → readiness_gate: diagnose_again

## 3. Readiness Gate — 6 种准备就绪判定

**来源: universal-diagnostic-tutor / readiness_gate_protocol.md**

每次理论教学或实践评测后，根据以下证据判定推进：

| 判定 | 触发条件（标注领域） | 动作 |
|------|-------------------|------|
| **Advance** | teach_back ≥ 2/2/2 且 confidence ≥ 7/10 且无重复错误模式 | 推进到下一个知识点/任务 |
| **Advance with caution** | teach_back 通过但 confidence 低，或近迁移表现弱但核心对 | "往前走，但下次开头先测一下这个是否巩固了" |
| **Review first** | teach_back 未通过但有明确可修复缺口（如只差一个子概念） | 回到对应错误处，局部修复后重新检查 |
| **Step down** | 当前知识点/任务依赖未掌握的前置条件 | 回到更基础的知识点/更简单的任务。用 `competency_map node=xxx` 查 `prerequisites`，定位最近未掌握的前置技能后回退 |
| **Diagnose again** | teach_back 失败但原因不明确，或多次干预无效 | 换一种 check 方式/不同角度重新诊断 |
| **More practice** | teach_back 勉强通过(2/2/2 但其中一项恰好在线上)或实践 F1 0.65-0.7 | 不出新内容，多给 1-2 个同类型的近迁移任务 |

**证据检查清单（从 readiness_gate 借用）：**
- 解释质量: 学生能否用自己的话说出核心概念？
- 实践正确性: 标注结果满足标准吗？
- 推理正确性: 方法选对了吗？理由对吗？
- 近迁移: 换个场景/数据能独立完成吗？
- 自信度信号: 推理的还是猜的？受提示的程度？
- 重复错误模式: 同样的概念/方法/设置错误是否复发？

## 4. Understanding Check — 7 种检查方式选择指南

**来源: universal-diagnostic-tutor / understanding_check_protocol.md**

| 检查类型 | 标注领域的适用场景 | 示例 |
|---------|-----------------|------|
| **One-Question** | 刚讲完 IOU 概念，需快速确认 | "IOU=0.5 够不够好？什么场景需要 IOU≥0.7？" |
| **Explain-It-Back** | 学生跟着走但不一定真懂了 | "用你自己的话解释 IOU 三个步骤" |
| **Classify-The-Method** | 学了多个指标容易混用 | "这个任务应该用 IOU/F1/Accuracy 中哪个？先判断再解释为什么" |
| **Predict-Next-Step** | 懂了概念但不会应用 | "给你两个框的坐标，算 IOU 的第一步是什么？只告诉我第一步不用算结果" |
| **Error-Spotting** | 一个常见错误在培训中强调过 | "有人把 IOU 算成了 0.8 但两个框明显完全偏离——他有什么地方弄错了？" |
| **Near-Transfer** | 刚完成 task1，准备推 task2 | "换个场景——视频标注中逐帧检查，IOU 的作用有什么不同？" |
| **Confidence** | 学生犹豫、不自信或过度自信 | "感觉 OK 了吗？0-10？再来一个例子还是继续？" |

## 5. 渐进提示梯触发条件

| 触发条件 | 提示等级 |
|---------|---------|
| 学生 60 秒无动作 / 说"不知道" | L0 诊断: "你卡在哪一步？" |
| L0 后仍无进展 | L1 概念问: 指向原理不命名 |
| L1 后仍卡住 | L2 类比: 从已知领域搭桥 |
| L2 后仍卡住 | L3 原理提醒: 命名但不展示步骤 |
| L3 后仍卡住 | L4 步骤提示: 指出下一步 |
| L4 后仍卡住 | L5 近完整支架: 平行例子 |
| **任何时刻** | **绝不直接给答案** |

**防 hint-abuse 机制（来自 education-agent-skills）:**
```
连续 3 次快速请求提示 → "在给下一个提示前，
 先告诉我上一个提示告诉了你什么？你从中学到了什么？"
→ 说不出 → 不给下一级
→ 说得出 → 正常推进
```

## 6. 理论↔实践路由决策

```
理论完成一个知识点后:
  │
  ├─ readiness = advance → 该知识点有对应练习？
  │   ├─ 是 → "验证一下 → 标注工作台" → Phase2
  │   └─ 否 → 推进下一个 Phase1 知识点
  │
  ├─ readiness = advance_with_caution → 有对应练习？
  │   ├─ 是 → Phase2 (同难度，但下次对话开头先测)
  │   └─ 否 → 推进知识点 (下次开头先测)
  │
  ├─ readiness = review_first → 回到 error_to_intervention 局部修复 → 重新检查
  ├─ readiness = step_down → 回到更基础知识点 → 重新走 Phase1
  ├─ readiness = more_practice → 给 1-2 近迁移 → 再测
  └─ readiness = diagnose_again → 换 check type → 重新评估

实践完成一个任务后:
  │
  ├─ readiness = advance → 同难度还有任务？→ 继续 : 升难度
  ├─ readiness = advance_with_caution → 推进 + 标记"下次检"
  ├─ readiness = review_first / step_down → 回 Phase1
  ├─ readiness = more_practice → 同难度给类似任务
  └─ 连续 3 次 readiness ≤ review → 强制 step_down + 减速
```

## 8. 标注 Rubric (多维评分) — learning-assessor 借用

标注评测不只看 F1。用四维 rubric 做综合判断:

| 维度 | 权重 | 测量方式 | 优秀 | 合格 | 需重修 |
|------|------|---------|------|------|--------|
| 框精度 | 35% | 逐框 IOU 均值 | ≥ 0.85 | ≥ 0.65 | < 0.5 |
| 标签准确性 | 30% | F1 Score | ≥ 0.93 | ≥ 0.85 | < 0.7 |
| 完整性(召回) | 25% | Recall | ≥ 0.95 | ≥ 0.85 | < 0.7 |
| 一致性 | 10% | 同类框尺寸/位置方差 | 稳定(方差小) | 轻微波动 | 显著不一致 |

**使用方式:**
- Phase2 Step5 分层反馈时: 先报 F1, 再按四维逐一判定
- 学生 F1=0.85 但某一维偏低: 聚焦该维度反馈,不是全量回滚
- 个人中心仪表盘: 雷达图四维展示

**学习分析 5 维度 (驱动个人中心数据模型):**
1. 知识掌握度 — F1 趋势 + 教学回授分数
2. 技能应用 — 各类型任务(bbox/分类)的独立成绩
3. 学习进度 — 完成知识点数/总数 + 练习任务数/总数
4. 学习困难 — 重复错误模式识别 + 耗时变动
5. 改进建议 — Coach 的 session_summary 汇总
